Filing a pin

The interaction that does not exist in Cork today. Pills on the card show where the pin already sits, which doubles as the visibility display. Picker rows carry sharing status inline. Checkboxes rather than a dropdown, because the control itself has to say a pin can be in several places. The consequence line names the board and the person, and appears only when a shared board is selected.

Board detail

The removal control names the board it applies to; that is the whole safety mechanism between a scoped action and a global one. They are textually different rather than two icons, and only the destructive one carries colour. Attribution shows a second name only when the creator and the placer differ. “Also on N boards” is the fix for apparent duplication and is deliberately muted.

Boards

Grouped by private and shared, which describes the board rather than a person’s standing in it. Shared comes first because that is where activity is. Every row lists all members including you, in the same voice, with no marker for who created it. This assumes flat permissions; a creator field that quietly grants power would contradict the framing.

Pins

Your own library. Its job is filing rather than browsing, which argues for a dense list. “Not on a board” is a filter and a row state, never a separate destination, so unfiled pins sit among filed ones instead of becoming a backlog. Every row carries a plus, so filing happens while scanning. This shows only pins you created, which leaves open how you get back to pins you found on someone else’s board.
